# v4.2.0 — foundations of the claims

Goal: every threshold, date and label the kit shows can be traced to an official source, or says plainly that it is a criterion of the kit or still to be verified. The review found real mistakes, so the checks that keep it aligned are now part of the gates.

## What is new

- **Claim register** (`criteria/v4/sources.json`, rendered in [docs/sources.en-US.md](sources.en-US.md) and [docs/sources.pt-BR.md](sources.pt-BR.md)). Each entry has the claim in EN-US and PT-BR, the checks that use it, the source URLs, the quoted evidence, the date it was verified and one of four states: **official source**, **official CVE record**, **kit criterion** (with a rationale) or **to verify** (with a to-do).
- **`tools/Test-ClaimRegister.py`**: fails when the collector gains a numeric threshold (version, date, number of days or months, price) that is not in the register, when a registered token no longer exists in the collector, or when a verified entry has no official URL, evidence or date. `tools/Sync-Sources.py --check` fails when the generated pages are stale.
- **`tools/Verify-Package.py`**: recomputes key numbers from the raw data of an evidence package (`data/*.json`) and compares them with `results.json`. Use it on any package, including a customer's: `python tools/Verify-Package.py <package.zip>`. `tools/Test-VerifyPackage.py` proves it accepts a consistent package and detects the mistakes found in real runs.

## Corrections found by the review

| Item | Before | Now |
|---|---|---|
| CHK-21 | Every open agent port was called SSH/WAC; 3389 was labelled RDP. | Only 22 (SSH) and 6516 (Windows Admin Center, per the Learn deployment examples) are named; other ports are unclassified; a 6516 without the `AdminCenter` extension is reported. |
| CHK-29, CVE list | Per-machine CVE ranges did not match the NVD records (CVE-2025-49692 and CVE-2025-55316 ranges were wrong; CVE-2025-26627 had no usable agent range). | Ranges follow NVD: below 1.49, below 1.56 and below 1.61. CVE-2025-26627 is no longer mapped per machine. |
| CHK-29, automatic upgrade | "Disabled on 0 of N" ignored that `automaticupgrade.blocklocally` takes precedence over the Azure property and cannot be read through Azure. | The detail states the limit, counts machines below 1.67 (not eligible) and failed attempts, and points to `azcmagent config get automaticupgrade.blocklocally` (CHK-36). |
| Agent calendar | The table stopped at 1.68. | 1.69 (October 2026) added, verified in the release notes. |
| Kit index | Described as "the Defender for Cloud Secure Score model". | Described as inspired by it: Microsoft uses a fixed maximum score per control; the severity weights are the kit's. |
| CHK-33 | Counted nested resources as machines (13 for 7 machines). | Fixed in v4.1.6; `Verify-Package.py` flags it on older packages (rule V21). |

## State of the register

The register lists which statements are still **to verify** (the 45-day expiry, the SQL extension minimum, the 24-hour usage upload, the 30-day pay-as-you-go limit, the Activity Log retention, Windows Server 2008 in ESU and the list prices). They are shown in the results but must not be presented as official until the to-do is closed.

## How the review proceeds

1. **Collector thresholds** (done in this version): every numeric threshold registered and tested.
2. **Guide and catalog texts** (next): each check's criterion and each guide statement gets a register id or an official link; the guide shows the state.
3. **Engine and report texts**: priority scale, scenarios and mappings are registered as kit criteria; the report will show the state next to each claim.
4. **Sample and scope**: every number says whether it is about the sample or the whole estate (CHK-37 still mixes both under `-MaxMachines`).
5. **Real packages**: run `Verify-Package.py` on the lab package and on a customer sample before delivery; any disagreement is a review item.
6. **Freshness**: entries with a `reviewBy` date (release calendar, SQL extension target, prices, ESU) are re-checked on that date.

## Verification method

A statement is marked as official only after the Microsoft page was opened in full and the quoted text supports it; summaries from search results are not accepted as evidence. The Arc agent support workbook (<https://github.com/fabiotreze/AzureArcBRTips/tree/main/workbooks/arc-agent-support>) is used as a corroborating source, not as an authority, and it reads agent properties the kit did not collect before (`agentUpgrade.desiredVersion`, `lastAttemptStatus`, `lastAttemptMessage`). The kit now collects `lastAttemptStatus` and `desiredVersion` as well.
