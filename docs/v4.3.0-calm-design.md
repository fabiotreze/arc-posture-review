# v4.3.0 — calm visual design

The browser app and the canonical v4 report mixed two generations of styling: a clean verdict on top of the analysis, then the older cards below it, and a v4 report with solid, saturated status colors. v4.3.0 gives both one calm, presentation-ready look. It changes presentation only.

## Design language

Taken from a navy-and-pale-blue operational guide used as a style reference (no content or branding was reused):

| Element | Before | Now |
|---|---|---|
| Header / hero | Blue gradient, bright | Flat navy (`#1f3050`) with a thin teal rule |
| Status badges (P0..P3, outcomes, coverage) | Solid red, orange, violet, green, blue with white text | Pale tints with dark text and a hairline border |
| Outcome bars and the index ring | Saturated fills | Soft tones; the ring is a proportion of the index (`conic-gradient`) |
| Tables | Gray header, plain rows | Navy header, zebra rows, one style in the app and the report |
| Section titles | Plain, accent bar | Numbered (`01`, `02`…) with a thin rule |
| Section purpose | Missing | One line under each v4 report section (what it answers) |
| KPI numbers | Bold, colored | Light weight, navy; the state is carried by a small tinted icon or a thin accent |
| Notes and callouts | Several competing bars | One calm callout style (pale blue, thin left accent) |

Status keeps its meaning through the label, the icon and the tint; color alone is never the only signal. Dark mode and print/PDF follow the same tokens.

## Structure changes in the app analysis

- The kit-index explanation is folded under "How the kit index is calculated" (the text is unchanged).
- The two reading notes (Semantics and the v4 report pointer) share one fold, "How to read this analysis".
- The Quick read no longer repeats the three top gains: they are in "Do first" at the top. Its short note explains what the `+N pts` gain means.
- The Executive assessment and the Evidence appendix are numbered parts.
- Fixed a stray `\1` that appeared next to the scope selector in "Prepare collection" (a regex artifact from v4.1.3).

## Where the styles live

- App pages, saved analyses and samples: the design tokens and all component styles are one block, `tools/report-responsive.css`, synced by `tools/Sync-ReportAssets.py`. The page itself no longer defines color tokens.
- Canonical v4 report: `assurance/v4/checkpoint6/report/render_v4.py` (`CSS` tokens, status tints in `STATUS_COLORS_CSS`, theme in `UX_CSS`). The `.badge.<STATUS>` selectors stay because `Test-StatusColors.py` requires a color rule for every status.

## Not changed

Collector logic, the 64 checks, results, scores, priorities, the canonical `assessment-result.v4` contract and every canonical text value. The report contract, the render-purity test, the localization parity test, the PDF matrix and the browser regression pass unchanged.

## Samples

`docs/examples/sample-analysis.*.html` are saved analyses of a sanitized lab package that is not part of the repository, so they cannot be regenerated here. Their markup was migrated to the new structure (ring, bars, folds) and they pick up the shared styles. Their content still predates the verdict card; regenerating them from a new sanitized package is tracked as a follow-up.
