## KI-V4-001 — pypdf Dependabot alerts

- **Status:** RESOLVED — remediated by upgrading the approved pin
- **Previous approved dependencies:** `pypdf==6.19.0`, then `pypdf==6.21.2`
- **Current approved dependency:** `pypdf==6.21.4`
- **Observed security queue before the first remediation:** 11 Dependabot alerts per requirements file (`requirements-v4.txt` and `requirements-dev.txt`)
- **Observed security queue before v4.1.1:** 14 Dependabot alerts (7 advisories x 2 requirements files) against `pypdf==6.21.2`; `6.21.4` is the first patched version for all of them.
- **Remediation:** both requirements files carry the new pin and the CP8/CP9/CP10 gates validate the resolved state. `pypdf` only reads PDFs generated by this project (`tools/Generate-CleanPdf.py` and the report visual test); it never parses user-supplied PDFs.
- **Effect:** the dependency blocker is closed. The v4.0.0 security review was repeated and approved on 2026-10-29 and v4.0.0 is published.

No workflow or integration script in this package bypasses the release gates or suppresses alerts.

## v4.1.1 review notes

Posture versus evidence: a missing configuration or missing evidence was reported as a conclusive FAIL in several checks, and a run without `-Subscriptions` silently queried only the CLI default subscription while reporting full coverage. Fixed in v4.1.1; see `docs/v4.1.1-posture-vs-evidence.md` and `docs/v4/security-review-record-v4.1.1.md`.

Still open (documented, not regressions): F3 (FAIL/WARN is not gated by missing required fields in the engine; the approved model allows a conclusive FAIL with PARTIAL coverage and the fixtures carry no `data/*.json` members), per-machine correlation by `resourceGroup/name` without subscription (the collector now warns when the same pair exists in more than one subscription), and CHK-37 mixing the machine sample with the whole-estate status counts when `-MaxMachines` is used.
