# Sources and foundation of the claims

Every threshold, date and label used by the collector and the reports is registered in `criteria/v4/sources.json` with the state of its foundation. This page is generated by `tools/Sync-Sources.py`; `tools/Test-ClaimRegister.py` fails when the collector gains a threshold that is not registered.

## How to read the state

- **Official source**: the Microsoft page was opened in full and the quoted statement supports the claim.
- **Official CVE record**: confirmed in the NVD record of the CVE, which cites the MSRC advisory.
- **Kit criterion**: a criterion of this kit, **not** a Microsoft recommendation; the rationale says why it exists.
- **To verify**: not yet confirmed in an official source; the result is shown but must not be presented as official until the to-do is closed.

### AGENT-AUTOUPGRADE-LOCALBLOCK — Official source

The local setting automaticupgrade.blocklocally takes precedence over the Azure property enableAutomaticUpgrade: when true, automatic upgrades are blocked even if the Azure property is true. It is read on the machine with 'azcmagent config get automaticupgrade.blocklocally', not through Azure.

- **Evidence:** "The automaticupgrade.blocklocally setting takes precedence over the enableAutomaticUpgrade property." The option was introduced in agent 1.61 (release notes: 'Added option to disable automatic upgrades locally').
- [Automatically upgrade the Azure Connected Machine agent (section: Block automatic agent upgrades locally)](https://learn.microsoft.com/en-us/azure/azure-arc/servers/automatic-agent-upgrade)

### AGENT-PORTS-CHANNELS — Official source

incomingconnections.ports lists the local ports the Azure Arc connectivity channel may reach (several ports are separated by commas). SSH uses port 22 by default (a single port per service configuration) and Windows Admin Center is deployed through the AdminCenter extension on a configurable port (the examples use 6516). Any other port is reported as unclassified.

- **Evidence:** WAC page: "azcmagent config set incomingconnections.ports <port> ... you can specify multiple ports separated by a comma"; deployment example `$wacPort = "6516"` with extension AdminCenter (publisher Microsoft.AdminCenter). SSH page: "You may only allow connection to a single port", default 22.
- [Manage Azure Arc-enabled servers using Windows Admin Center in Azure](https://learn.microsoft.com/en-us/windows-server/manage/windows-admin-center/azure/manage-arc-hybrid-machines)
- [SSH access to Azure Arc-enabled servers](https://learn.microsoft.com/en-us/azure/azure-arc/servers/ssh-arc-overview)
- [CLI reference for azcmagent config](https://learn.microsoft.com/en-us/azure/azure-arc/servers/azcmagent-config)

### KIT-INDEX — Kit criterion

The kit index is not the Defender for Cloud Secure Score. Microsoft gives each control a fixed maximum score and divides it by the healthy and unhealthy resources; the kit weights controls by severity (High 3, Medium 2, Low 1) and scores them by the share of healthy machines.

- **Evidence:** Learn: "Max score ... is fixed for every environment"; "Score per resource = max score / (healthy + unhealthy resources)".
- **Rationale:** A reading aid to rank work inside this report. The official measure is the Secure Score of Defender for Cloud.
- [Cloud Secure Score in Microsoft Defender for Cloud](https://learn.microsoft.com/en-us/azure/defender-for-cloud/secure-score-security-controls)

### PRIORITY-SCALE — Kit criterion

Residual risk scores map to priorities P0 (80 or more), P1 (60), P2 (35) and P3. It prioritizes posture work; it is not an incident severity.

- **Rationale:** Deterministic model defined by this project (checkpoint 3 and 4); documented in docs/v4/methodology-v4.md.

### SCENARIOS-AS — Kit criterion

The 11 security scenarios (AS01-AS11) and their attack paths are hypotheses written by the author; an attack is never asserted as confirmed.

- **Rationale:** Scenarios link controls to a reading of risk. They carry attackConfirmation=NOT_ASSERTED.

### MCSB-ZT-MAPPING — Kit criterion

The mapping of each check to Microsoft Cloud Security Benchmark controls, Zero Trust principles and pillars, and tiers is the author's reading, with a mapping confidence per check.

- **Rationale:** Reading aid; not a compliance mapping. See mappingConfidence in assurance/v4/checkpoint3/data/checks.enriched.json.
