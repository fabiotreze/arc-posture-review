# v4.1.1 posture versus evidence

## Scope

This patch separates **observed posture** from **missing evidence or missing configuration**, discloses an implicit collection scope, and restates the executive summary of the v4 report in report form. It adds no checks or scenarios and collects no customer data. It also moves the approved `pypdf` pin to `6.21.4`.

## Preserved contracts

- Exactly 64 controls (`CHK-01..CHK-64`) and 11 scenarios (`AS01..AS11`).
- Canonical assessment contract `assessment-result.v4`, contract version `4.0.0` (the optional action-card field `basis` is added; the pipeline version is `4.1.1-checkpoint5`).
- Collector input schema version 3.
- Control Result and Evidence Coverage remain independent axes; stored enums (`PASS`, `WARN`, `FAIL`, `INEFFECTIVE`, `AT_RISK`, `UNASSESSED`) are unchanged.

## Reading rule

| Report wording | Contract value | Meaning |
|---|---|---|
| Verified gap | `INEFFECTIVE` | A condition observed with enough evidence (for example NonCompliant, an expired agent, a Free Defender tier). |
| Improvement opportunity | `AT_RISK` | A hardening or visibility step that is not configured. It does not mean a practice is insecure. |
| Not verified | `UNASSESSED` | Evidence was not collected, is documentary, or is outside the collected scope. It is a collection task, not a finding. |

A posture weakness is never evidence of exploitation; `attackConfirmation` stays `NOT_ASSERTED`.

## Collector rules changed

- **CHK-01** returns `PARTIAL` (not an inventory conclusion) when no `-Subscriptions` or `-ManagementGroup` was supplied and the default subscription holds no Arc machine. The run also prints a warning and the detail states the implicit scope.
- **CHK-23** is `WARN` (hardening opportunity) when a machine accepts any extension; it is no longer `FAIL` when at least half do.
- **CHK-56** is `WARN` (visibility gap) when the local-administrators audit is not configured on any connected Windows machine; it is no longer `FAIL`.
- **CHK-31** is `FAIL` only for an explicit Free tier; an unreadable plan is `PARTIAL`.
- **CHK-43** is `FAIL` only for a subscription whose diagnostic settings were read and have no export; an unreadable subscription is `PARTIAL`.
- **CHK-18** is `FAIL` only when `publicNetworkAccess` is returned and is not `Disabled`; a missing value is `PARTIAL`.
- **CHK-33** returns `PASS` for zero recommendations only when Defender for Servers is Standard in every subscription; otherwise `PARTIAL`.
- **CHK-41** is `PARTIAL` when the Activity Log is exported to a workspace outside the collected scope and no Sentinel is found in scope.
- **CHK-45** is `PARTIAL` (not `N/A`) when the DCRs send data only to workspaces outside the collected scope.
- N/A results carry `FULL` evidence coverage, so the engine can prove non-applicability (item F5 of the v4.0.3 addendum).
- The collector warns when the same resource group and machine name exist in more than one subscription.

CHK-55 is unchanged: explicit `NonCompliant` Machine Configuration evidence is a conclusive `FAIL`; machines without a returned assignment remain `PARTIAL`.

## Engine and report changes

- A scenario whose only triggers are not verified controls cannot score above P2 and never reaches the NOW horizon.
- A defense function whose controls are only informational or not applicable is `UNKNOWN`, never `EFFECTIVE`.
- Each action card carries `basis`: `VERIFIED_GAP`, `IMPROVEMENT` or `EVIDENCE_COLLECTION`. Containment wording is reserved for verified gaps; the other bases use posture or evidence work wording and actions.
- The executive summary lists verified gaps, improvement opportunities and not-verified controls with check titles, keeps the canonical codes and the legend, and groups the action plan by what to do.

## Regression coverage

`tools/Test-PostureWording.py` runs the collector blocks against stubbed data: absence of configuration or evidence is `WARN` or `PARTIAL`, and explicit adverse evidence stays `FAIL`. It is registered in the checkpoint 4 gate.

## Not changed (documented in `docs/v4/known-issues.md`)

- F3: the engine does not gate `FAIL`/`WARN` on missing required fields.
- Per-machine correlation by `resourceGroup/name` without the subscription.
- CHK-37 mixes the machine sample with whole-estate counts when `-MaxMachines` is used.
