# v4.1.4 — posture wording and a complete pt-BR report

Found in the first end-to-end run in Cloud Shell (v4.1.3).

## What changed

- **Action cards:** verified-gap cards were titled *Contain and remediate* and listed incident-response steps (*preserve timestamped evidence*, *contain the exposed boundary*). A posture assessment never asserts an incident, so they now read **Remediate: …** with posture steps (confirm the gap, remediate by severity under change control, re-run the collection, record owner and date) and closure criteria. Improvement and evidence-collection cards are unchanged. Priorities and scores are unchanged.
- **pt-BR report:** engine texts (card titles, actions, closure, rollback, scenario names and hypotheses, security boundaries, guardrail) and the collector's detail, criterion and observation sentences now appear in Portuguese. The translation is display-only: the canonical JSON embedded in the report is identical in both languages. Names that come from Azure (Defender assessment names, resource names, values) stay as collected.
- **Rules shared with the app:** `criteria/v4/pt-br-detail-rules.json` mirrors the Portuguese rules of the app (`PT_DETAIL_RULES`), plus the new ones. `tools/Test-PtBrContent.py` fails if they diverge. A rule-order bug that produced mixed text such as "7 connected máquina(s)" is fixed in both.
- **Collector trace:** `run.log` is closed before the report step (it is hashed in `manifest.json`), so the step is now recorded in `report/report.log` (collector version, time, where the engine came from).

## Still open

- Priorities: scenarios with a high residual score are still P0 (NOW). The scale is unchanged on purpose; it is a prioritization of posture work, not an incident severity.
- Sentences that the collector can produce but did not appear in a real run may still be English in the pt-BR report; add a rule to the app table and regenerate the JSON.
- The engine does not yet gate FAIL/WARN on missing required fields (F3).
