# v4.1.2 single package

## Problem

Since v4.1.0 the collector produced only the evidence `.zip`, while the README promised a v4 report generated by default and a separate `…-v4.zip`. Getting the canonical v4 report (Zero Trust × Tier, scenarios, action plan) required cloning the repository and running three Python commands, and the app could not show it.

## What changes

1. **One package.** After writing the evidence and its manifest, the collector evaluates the run with the same engine used by the CLI, renders the report in EN-US and PT-BR and adds `report/arc-posture-review.v4.en-US.html`, `report/arc-posture-review.v4.pt-BR.html` and `report/assessment.v4.json` to the same `.zip`. The `.zip.sha256` covers the final package.
2. **The app opens it.** When the loaded `.zip` has `report/`, step 4 shows *Open v4 report (Zero Trust)* and *Save v4 report (.html)* (EN-US or PT-BR to match the app language). Saving applies the *Hide e-mails* option. The `report/` folder is not flagged as a file outside the manifest; manifest-listed files are still verified.
3. **Where the engine comes from.** From the clone when the script runs inside one; otherwise from `arc-posture-kit.zip`, published as a release asset next to the script. The kit is 16 stdlib-only Python and data files, built deterministically by `tools/Build-Kit.py` (sorted entries, fixed timestamps, stored, LF text). Its SHA-256 is pinned in the collector (`$KitSha256`) and the download is refused on mismatch. `-KitUrl` accepts another URL or a local path for offline use.
4. **Graceful failure.** If Python 3.10+ is missing, the download fails or the hash differs, the collector warns, removes any partial `report/` and finishes with the evidence package. `-NoV4Report` skips the step.

## Integrity model

`manifest.json` lists the evidence files written before the report. The report is generated from that evidence and is not itself listed; the report records the digest of the evidence package it was rendered from. Re-running the CLI on the final `.zip` yields an equivalent report with the digest of the final package.

## Preserved contracts

64 checks, 11 scenarios, `assessment-result.v4` contract version `4.0.0`, collector schema version 3, read-only Azure access (the report step runs locally and calls no Azure API).

## Regression coverage

- `tools/Build-Kit.py --check`: the pinned SHA-256 equals the built kit (checkpoint 4 gate; release workflow).
- `tools/Test-V4ReportStep.py`: report generated from a run folder; a kit is accepted only with the pinned SHA-256.
- `tools/Test-AppV4Report.py`: buttons appear only when `report/` exists, no manifest warning, the report opens and saves in EN-US and PT-BR (checkpoint 6 gate; release workflow).

## Release steps added

After changing any kit file or `VERSION`: `python tools/Build-Kit.py --write-hash`, then `python tools/Sync-ReportAssets.py`, then `python tools/Prepare-Release.py checksums`. The release workflow rebuilds `arc-posture-kit.zip`, fails if its SHA-256 differs from the pinned value and uploads it with the script.
